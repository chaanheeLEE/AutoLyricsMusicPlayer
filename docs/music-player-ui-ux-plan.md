# 음악 플레이어 UI·UX 구조 개선 계획서

## 1. 프로젝트 개요

### 1.1 목적
기존 음악 플레이어의 기능을 유지하면서 감상과 편집의 역할을 분리하고, 정보의 우선순위와 일관된 레이아웃을 통해 정돈되고 고급스러운 사용 경험을 구현한다.

### 1.2 기본 방향
- 색상 선택보다 화면 구조와 기능 배치를 먼저 결정한다.
- 여러 테마에서도 레이아웃, 조작 방식, 정보 위계는 동일하게 유지한다.
- 기본 화면은 음악 감상에 집중하고, 가사 보정과 분석 도구는 편집 화면으로 분리한다.
- 기능을 삭제하기보다 필요한 시점에 노출한다.
- 이 문서의 크기와 배치는 설계 제안이며 구현 후 실제 화면에서 조정한다.

## 2. 현행 화면의 개선 과제

| 현행 구성 | 문제 및 개선 방향 |
|---|---|
| 왼쪽 패널에 재생·싱크·분석·내보내기 집중 | 기능을 사용 목적에 따라 분리 |
| 가사 한 줄마다 카드와 시간 표시 | 감상에서는 글자와 여백 중심, 편집에서는 시간 표시 |
| 가사 아래에 재생 목록 상시 노출 | 필요할 때 여는 대기열 패널로 전환 |
| 싱크 조정 도구 상시 노출 | 가사 편집 화면에서 제공 |
| 분석·내보내기와 재생 조작이 비슷한 강조 수준 | 핵심 조작과 보조 도구의 시각적 우선순위 구분 |
| 긴 파일명을 곡 제목으로 표시 | 제목·아티스트·파일 정보 분리 |

## 3. 정보 구조와 화면 구성

### 3.1 주요 화면
1. 감상: 앨범 커버, 곡 정보, 동기화 가사 중심.
2. 라이브러리: 추가한 음악 전체를 검색·정렬·관리.
3. 가사 편집: 가사 내용과 시간 수정, 분석, 내보내기.
4. 설정: 테마와 앱 공통 설정.

### 3.2 공통 영역
- 상단: 화면 이동과 현재 화면의 주요 도구.
- 중앙: 선택한 화면의 주 콘텐츠.
- 하단: 모든 주요 화면에서 유지되는 공통 재생바.
- 우측 보조 패널: 재생 대기열 등 일시적으로 확인하는 정보.

초기에는 상단의 감상·라이브러리 내비게이션을 사용한다. 탐색 항목이 늘어날 때 좌측 사이드바 도입을 검토한다.

### 3.3 감상 화면 와이어프레임

```text
┌────────────────────────────────────────────────────────────┐
│ 앱 이름       감상 / 라이브러리           가사 편집  목록  설정 │
├────────────────────────────────────────────────────────────┤
│                                                            │
│   앨범과 곡 정보                 동기화된 가사               │
│                                                            │
│   ┌────────────────┐            이전 가사                   │
│   │                │                                       │
│   │    앨범 커버    │            현재 가사                   │
│   │                │                                       │
│   └────────────────┘            다음 가사                   │
│                                                            │
│   곡 제목                                                  │
│   아티스트                                                 │
├────────────────────────────────────────────────────────────┤
│                  재생 진행 막대                             │
│ 현재 곡      셔플  이전  재생  다음  반복      볼륨  가사 창   │
└────────────────────────────────────────────────────────────┘
```

## 4. 감상 화면 상세 계획

### 4.1 앨범과 곡 정보
- 앨범 커버는 정사각형으로 크게 배치한다.
- 커버 아래에 곡 제목과 아티스트를 구분해 표시한다.
- 파일명 전체와 경로는 곡 정보 메뉴로 이동한다.
- 메타데이터가 없으면 파일명을 대체 제목으로 사용하고 확장자는 숨긴다.
- 가사 준비 상태는 작은 상태 표시로 제공한다.
- 앨범과 곡 정보를 다시 큰 테두리 카드로 감싸지 않는다.

### 4.2 가사 표시
- 행별 카드, 테두리, 타임스탬프를 감상 화면에서 제거한다.
- 현재 가사는 크기·굵기·명도로 강조한다.
- 이전·다음 가사는 보조 텍스트로 표시한다.
- 가사 블록은 왼쪽 정렬하며 중앙 콘텐츠 영역에 배치한다.
- 사용자가 직접 스크롤하면 자동 추적을 잠시 멈춘다.
- 수동 탐색 중에는 `현재 가사로 이동` 버튼을 제공한다.
- 가사 강조 방식은 테마가 바뀌어도 일관되게 유지한다.

## 5. 공통 재생바

| 위치 | 구성 |
|---|---|
| 상단 얇은 줄 | 탐색 가능한 재생 진행 막대 |
| 왼쪽 | 작은 앨범 커버, 곡 제목, 아티스트 |
| 중앙 | 셔플, 이전, 재생·일시정지, 다음, 반복 |
| 오른쪽 | 볼륨, 플로팅 가사, 재생 대기열 |

### 설계 원칙
- 감상·라이브러리·편집 화면 전환 시에도 재생 상태와 위치를 유지한다.
- 재생·일시정지를 가장 중요한 버튼으로 표시한다.
- 보조 버튼은 아이콘 중심으로 정리하고 모든 버튼을 개별 박스로 감싸지 않는다.
- 호버, 선택, 키보드 포커스 상태를 구분한다.
- 외부 플로팅 가사는 `가사 창`, 내부 수정 기능은 `가사 편집`으로 명칭을 구분한다.

## 6. 가사 편집 화면

### 6.1 구조
작은 팝업 대신 중앙 콘텐츠를 편집 화면으로 전환한다. 좌측에는 시간과 가사 목록, 우측에는 선택한 줄의 수정 도구를 배치한다.

```text
┌────────────────────────────────────────────────────────────┐
│ 감상으로 돌아가기     곡 제목             저장  내보내기     │
├───────────────────────────────────┬────────────────────────┤
│ 가사 목록                         │ 선택한 줄 편집         │
│                                   │                        │
│ 00:05.000   첫 번째 가사           │ 가사 내용              │
│ 00:09.000   두 번째 가사           │ 시작 시각              │
│ 00:11.000   선택한 가사            │ 미세 시간 조정         │
│ 00:17.000   다음 가사              │                        │
│                                   │ 전체 싱크 조정         │
│                                   │ 재분석 / AI 재정렬     │
├───────────────────────────────────┴────────────────────────┤
│ 확장 기능: 오디오 파형과 가사 시작 지점                     │
├────────────────────────────────────────────────────────────┤
│ 공통 재생바                                                │
└────────────────────────────────────────────────────────────┘
```

### 6.2 기능 배치

| 기능 | 위치 |
|---|---|
| 가사 내용·시작 시각 수정 | 우측 선택 줄 편집 패널 |
| 선택한 줄 미세 시간 조정 | 우측 선택 줄 편집 패널 |
| 전체 오프셋 조정·초기화 | 우측 패널의 별도 그룹 |
| 재분석·AI 재정렬 | 분석 도구 메뉴 |
| LRC·VTT 내보내기·오디오 삽입 | 내보내기 메뉴 |
| 캐시 삭제 | 곡별 고급 메뉴 또는 설정 |

### 6.3 편집 범위 구분
- `선택한 줄 조정`과 `곡 전체 조정`을 제목과 설명으로 명확히 구분한다.
- 화면 전환 시에도 재생 위치를 유지한다.
- 오디오 파형은 초기 개편의 필수 범위에서 제외하고 후속 단계로 둔다.

## 7. 라이브러리와 재생 대기열

### 7.1 라이브러리
앱에 추가한 모든 음악을 관리하는 독립 화면으로 구성한다.

- 상단: 검색, 정렬, 음악 추가.
- 본문: 곡 제목, 아티스트, 재생 길이, 가사 상태.
- 현재 재생 중인 곡에는 재생 상태 아이콘 표시.
- 긴 파일명은 상세 정보에서 확인.
- 곡별 보조 동작은 행 메뉴로 제공.

```text
곡 제목                   아티스트        길이     가사 상태
─────────────────────────────────────────────────────────
곡 이름                   아티스트        3:26     준비됨
곡 이름                   아티스트        4:12     분석 필요
```

### 7.2 재생 대기열
- 현재부터 재생할 곡과 순서를 보여주는 우측 보조 패널로 제공한다.
- 감상 화면의 가사 영역을 항상 점유하지 않도록 한다.
- 대기열에서 제거, 라이브러리에서 제거, 실제 파일 삭제를 서로 다른 동작으로 구분한다.

## 8. 공통 디자인 규칙

### 8.1 여백과 그룹화
모든 영역을 카드로 감싸기보다 정렬과 간격으로 묶는다. 구분이 부족한 영역에만 배경 차이나 얇은 구분선을 적용한다.

| 요소 | 초기 설계 기준 |
|---|---|
| 작은 아이콘과 텍스트 사이 | 8px |
| 같은 그룹 내 요소 간격 | 12~16px |
| 서로 다른 그룹 간격 | 24~32px |
| 화면 외곽 여백 | 24~40px |
| 일반 버튼 높이 | 36~40px |

위 수치는 시작 기준이다. 실제 창 크기와 콘텐츠 길이에 따라 조정하되 동일한 역할에는 동일한 규칙을 적용한다.

### 8.2 타이포그래피와 시각적 위계
- 일반 UI는 소수의 글자 크기 단계로 정리한다.
- 곡 제목과 현재 가사는 별도의 강조 대상으로 둔다.
- 앱 제목, 섹션 제목, 버튼을 모두 크고 굵게 표시하지 않는다.
- 색상뿐 아니라 크기, 굵기, 위치, 여백으로 중요도를 전달한다.
- 선택 상태는 색상만으로 표현하지 않고 아이콘이나 굵기를 함께 활용한다.

### 8.3 다중 테마 구조
컴포넌트에 색상을 직접 지정하지 않고 의미 기반 토큰을 사용한다.

```css
:root {
  --surface-app: /* 앱 배경 */;
  --surface-panel: /* 패널 배경 */;
  --surface-hover: /* 호버 배경 */;
  --surface-selected: /* 선택 배경 */;

  --text-primary: /* 주요 텍스트 */;
  --text-secondary: /* 보조 텍스트 */;
  --text-disabled: /* 비활성 텍스트 */;

  --border-subtle: /* 약한 구분선 */;
  --accent: /* 핵심 강조 */;
  --focus-ring: /* 키보드 포커스 */;

  --status-success: /* 성공 */;
  --status-warning: /* 주의 */;
  --status-error: /* 오류 */;
}
```

위 코드는 토큰 명세용 예시이며 실제 적용 시 각 값에 유효한 색상을 지정한다.

테마가 달라져도 버튼 크기, 패널 간격, 정보 위계, 가사 강조 방식은 유지한다. 구체적인 색상 팔레트는 구조 검증 후 결정한다.

## 9. 구현 단계와 완료 기준

### 1단계: 공통 재생바 분리
- [ ] 하단 재생바 구현.
- [ ] 기존 패널의 중복 재생 조작 제거.
- [ ] 화면 전환 시 현재 곡과 재생 위치 유지 확인.

### 2단계: 감상·편집 분리
- [ ] 싱크 조정과 분석 기능을 편집 화면으로 이동.
- [ ] 내보내기 기능을 하나의 메뉴로 통합.
- [ ] 감상 화면에서 편집 도구가 상시 노출되지 않는지 확인.
- [ ] 선택한 줄과 곡 전체의 조정 범위를 명확히 구분.

### 3단계: 감상 화면 완성
- [ ] 가사 행별 카드와 타임스탬프 제거.
- [ ] 앨범 커버·곡 정보·가사의 크기와 여백 정리.
- [ ] 수동 스크롤과 현재 가사 복귀 동작 구현.
- [ ] 긴 곡 제목과 메타데이터 없는 파일 표시 확인.

### 4단계: 재생 대기열 분리
- [ ] 우측 패널 열기·닫기 구현.
- [ ] 가사와 대기열이 상시 공간 경쟁하지 않도록 조정.
- [ ] 대기열 제거와 라이브러리 제거 동작 구분.

### 5단계: 공통 디자인 체계 정리
- [ ] 간격·글자 크기·버튼 규칙 통일.
- [ ] 의미 기반 색상 토큰 적용.
- [ ] 호버·선택·포커스 상태 정리.
- [ ] 테마 변경 시 레이아웃과 위계 유지 확인.

### 6단계: 후속 확장
- [ ] 라이브러리 검색·정렬·관리 화면 확장.
- [ ] 필요에 따라 좌측 사이드바 도입 검토.
- [ ] 오디오 파형과 가사 시작 지점 편집 기능 검토.

## 10. 초기 개편 범위

### 포함
- 공통 재생바.
- 감상 화면 재배치.
- 기존 가사 편집·분석·내보내기 기능의 위치 재구성.
- 접을 수 있는 재생 대기열.
- 공통 UI 규칙과 테마 토큰 기반 마련.

### 후순위
- 최종 색상 팔레트 확정과 테마별 세부 조정.
- 오디오 파형 편집.
- 탐색 항목 증가에 따른 대형 사이드바.
- 라이브러리 관리 기능 확장.

## 11. 최종 설계 목표
음악을 들을 때는 앨범과 가사에 집중하고, 수정할 때는 시간과 도구에 집중하도록 한다. 첫 개편은 새로운 기능 추가보다 기존 기능의 위치, 노출 시점, 시각적 우선순위를 재정리하는 데 초점을 맞춘다.
